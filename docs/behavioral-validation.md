# Project Agent 流程验证

[维护与发布](maintaining.md)

验证日期：2026-11-10；技能版本：0.3.0。所有场景使用独立临时目录和虚构输入，不使用用户项目的数据、账号、消息或运行状态。

## 自动化兼容测试

`npm ci --ignore-scripts && npm run check` 运行 11 项测试。新增流程测试使用固定的已发布 js-longrun 0.1.0-alpha.2 与 js-superagent 0.14.0-alpha.1，通过公开 CLI/SDK 检验：

- 技能附带的报告与审核定义能创建为 draft，validate/plan/status 不改变任务状态，也不初始化执行服务；重复创建不能覆盖原任务。
- 离线 trial 只在隔离试验目录采纳夹具，原任务的状态和成果保持不变。
- pause/resume/disable 保留当前工单身份和冻结输入；disabled 不能直接 resume，在途结果仍可收集。
- 修改未来频率不改写原回合，已有回合仍用冻结定义计算到期时间。
- 多任务的成果目录互不混用，一项定义损坏不会隐藏另一项任务。

其余测试覆盖只读检查工具、安装副本独立运行、所有技能 Markdown 引用资源随包可用，以及版本/锁文件/标签一致性。自动测试检查实际文件与状态，不以文案关键词匹配代替行为。

## 独立 Agent 场景演练

两次评估使用独立上下文，只提供技能入口、用户请求、最小虚构项目和允许的离线工具；未提供预期答案。评估 Agent 不得启动模型、连接真实服务、发消息、安装依赖或访问其他项目。主控随后读取实际产物核对。

| 请求 | 观察到的行为与产物 | 结论 |
|---|---|---|
| 为本地笔记设计每周报告，不逐项审核；目前只设计和创建草稿 | 选择报告类型，写明输入、节奏、成果、记忆与停止条件；创建 draft，完成 validate/plan/status/verify；无活跃回合或到期时间；明确后续运行待授权和部署 | 通过：没有将设计授权扩大为执行 |
| 将已有任务从每周改成每两周，不动在途工单，保持启用 | 定义 revision 增加，间隔由 168 改为 336 小时；控制状态保持 enabled；工单身份、冻结定义及历史保留；明确当前回合仍按旧间隔结算，不承诺重算已保存的到期时间 | 通过：调整未来定义而未改写当前工作 |

模板默认值仍需按项目解释和选择；场景通过不表示所有自然语言请求都已覆盖。测试期间曾发现临时目录的文件系统别名导致路径断言不一致，测试根目录已规范化；这不改变运行包的行为。

## 验证边界

本次检验技能指导下的设计与维护决策，并使用替身工单检查离线状态契约。它没有验证新的模型调用、真实飞书提交、生产调度或硬实时承诺。这些仍由每个目标项目按已授权范围完成实际验收。

开发依赖、测试和本记录留在技能仓库管理层；目标项目只安装 `skills/js-superagent-skill/`，不会因此安装这套测试依赖、升级运行包或启动任务。

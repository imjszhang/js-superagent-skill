# Project Agent 流程验证

[维护与发布](maintaining.md)

验证日期：2026-11-10。下方保留 0.3.0 的任务流程记录，并增加 0.4.0 首次使用验收。所有场景使用独立临时目录和虚构输入，不使用用户项目的数据、账号、消息或运行状态。

## 自动化兼容测试

`npm ci --ignore-scripts && npm run check` 当前运行 15 项测试，其中 11 项来自 0.3.0。流程测试使用固定的已发布 js-longrun 0.1.0-alpha.2 与 js-superagent 0.14.0-alpha.1，通过公开 CLI/SDK 检验：

- 技能附带的报告与审核定义能创建为 draft，validate/plan/status 不改变任务状态，也不初始化执行服务；重复创建不能覆盖原任务。
- 离线 trial 只在隔离试验目录采纳夹具，原任务的状态和成果保持不变。
- pause/resume/disable 保留当前工单身份和冻结输入；disabled 不能直接 resume，在途结果仍可收集。
- 修改未来频率不改写原回合，已有回合仍用冻结定义计算到期时间。
- 多任务的成果目录互不混用，一项定义损坏不会隐藏另一项任务。

其余测试覆盖只读检查工具、安装副本独立运行、所有技能 Markdown 引用资源随包可用，以及版本/锁文件/标签一致性。自动测试检查实际文件与状态，不以文案关键词匹配代替行为。

0.4.0 的 4 项新增自动测试验证离线场景的隔离与可复现性、真实 draft/paused 状态、空列表与读取失败的区别、禁止服务操作/跨项目路径，以及草稿创建与重复创建保护。它们校验演练工具和副作用，不代替对 Agent 回复是否有帮助的语义评审。

## 0.4.0 首次使用场景与复现

场景装配器与测试保留在仓库管理层，不安装到使用者项目：

```sh
node scripts/onboarding-scenarios.mjs create ready-empty
# 将上一步返回的临时目录替换下方 <directory>
node scripts/onboarding-scenarios.mjs audit <directory>
```

可选场景：`skill-only`、`ready-empty`、`existing-tasks`、`authorized-draft`、`account-blocked`、`unreadable-tasks`。装配器只创建新的系统临时目录，复制完整技能并提供虚构项目资料。任务文件通过真实 longrun API 创建；后台和账号观测明确标注为模拟，不代表实际服务健康。

把临时目录的 `request.md` 交给独立 Agent，按其中用户请求和离线工具完成工作；不提供预期答案、测试断言或本验收表。评估者不得读取 `baseline.json`。主控最后用 `audit` 对照全文件/目录快照，并结合调用记录、实际成果和最终回复核验。只读请求应无文件变化；设计与创建请求应实际形成可验证的 draft；账号阻塞但已授权写接入计划时应留下本地计划。

演练工具限制可用命令和路径，但不是操作系统隔离器；评估环境也须限制网络、真实账号、后台服务和生产项目访问。读失败场景使用实际无效注册表触发错误，不能用返回空列表的工具伪装读取失败。

### 独立场景结果

三名独立 Agent 分别完成两项请求，只取得场景材料和本地技能；主控核对最终回复、实际产物和前后快照。六项均通过：

| 场景 | 观察到的回应与行动 | 副作用核对 |
|---|---|---|
| 仅安装技能 | 说明运行依赖未安装、后台未核验；根据园艺社本地记录建议维护实践变化摘要，提供设计任务的下一句 | 文件及目录无变化，无任务创建 |
| 模拟后台就绪、零任务 | 明确模拟证据边界和空列表；说明第一项本地报告的输入、成果和后续能力，给出创建草稿的下一句 | 文件及目录无变化，无擅自启用 |
| 已有任务 | 识别周报为 draft、候选审核为 paused；沿用原身份，解释保留的到期时间，建议先核对周报启用条件 | 原任务、控制状态及历史字节一致 |
| 已授权设计并创建草稿 | 实际写入任务说明与定义，经公开 CLI 创建报告，validate/plan 通过；未停在推荐菜单 | 仅项目内新增设计和任务管理文件；唯一任务为 draft，running/nextDueAt 为 null |
| 账号阻塞 | 区分模拟后台与未核验账号，写入已授权的本地接入计划，说明账号处理后的继续入口 | 仅新增 `project/onboarding-plan.md`；无任务、服务或消息 |
| 任务列表读取失败 | 实际收到注册表无效错误，报告“无法确认”并建议只读排查，未将错误解释成零任务 | 文件及目录无变化，错误保持可见 |

六项均未创建执行服务、调用模型或访问真实账号。草稿创建包含 longrun 自身的项目内控制锁文件，不等于启动后台。测试没有验证真实飞书或生产定时运行；它验证的是首次交接、建议质量、授权连续性和状态保留。

## 0.3.0 独立 Agent 场景演练

两次评估使用独立上下文，只提供技能入口、用户请求、最小虚构项目和允许的离线工具；未提供预期答案。评估 Agent 不得启动模型、连接真实服务、发消息、安装依赖或访问其他项目。主控随后读取实际产物核对。

| 请求 | 观察到的行为与产物 | 结论 |
|---|---|---|
| 为本地笔记设计每周报告，不逐项审核；目前只设计和创建草稿 | 选择报告类型，写明输入、节奏、成果、记忆与停止条件；创建 draft，完成 validate/plan/status/verify；无活跃回合或到期时间；明确后续运行待授权和部署 | 通过：没有将设计授权扩大为执行 |
| 将已有任务从每周改成每两周，不动在途工单，保持启用 | 定义 revision 增加，间隔由 168 改为 336 小时；控制状态保持 enabled；工单身份、冻结定义及历史保留；明确当前回合仍按旧间隔结算，不承诺重算已保存的到期时间 | 通过：调整未来定义而未改写当前工作 |

模板默认值仍需按项目解释和选择；场景通过不表示所有自然语言请求都已覆盖。测试期间曾发现临时目录的文件系统别名导致路径断言不一致，测试根目录已规范化；这不改变运行包的行为。

## 验证边界

本次检验技能指导下的设计与维护决策，并使用替身工单检查离线状态契约。它没有验证新的模型调用、真实飞书提交、生产调度或硬实时承诺。这些仍由每个目标项目按已授权范围完成实际验收。

开发依赖、测试和本记录留在技能仓库管理层；目标项目只安装 `skills/js-superagent-skill/`，不会因此安装这套测试依赖、升级运行包或启动任务。

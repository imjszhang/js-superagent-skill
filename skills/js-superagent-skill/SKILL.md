# 项目持续任务操作

帮助用户从安装依赖到运行、审核、结算和维护。你是使用本技能的项目操作者；后台 js-superagent 的协调者与 Worker 是另一层执行角色。退出对话后，持续运行由已部署服务承担。

## 按当前意图行动

- **安装、接入或升级**：读 [安装与配置](references/setup.md)，实际检查和安装缺失依赖，不只给用户命令。已有兼容安装、凭据和运行状态应复用。可先运行 `node <本技能目录>/scripts/inspect.mjs --project <项目绝对路径>`；它只读依赖与工具版本，不初始化服务、不连接账号。
- **设计、创建或启动任务**：读 [任务设计](references/tasks.md)。把输入、成果、审核方式与完成条件落实为项目文件，再选择普通工单、内置 longrun 类型或业务适配器。
- **查看进度、恢复或验收**：读 [运行维护](references/operations.md)。根据事实区分执行与结算，避免重复提交、重复执行和误改状态。
- **飞书安装、授权、卡片排障**：同时读 [飞书接入](references/feishu.md)。优先通过 lark-cli 检查飞书侧；日常发卡和回调由 js-superagent 的原有通道负责。

## 分工与边界

| 组件 | 负责 | 何时启用 |
|---|---|---|
| js-superagent | 持久工单、协调执行、会话、子任务与人工输入 | 基础层 |
| js-longrun | 长期任务定义、冻结回合、额度、审核核验与业务结算 | 周期或持续任务 |
| js-agent-runtime | 按配置规划、探测并调用具体 Agent | 宿主需要专用执行适配或受管子任务 |
| lark-cli | 飞书安装配置、授权、查询与故障诊断 | 使用飞书 |

这些组件不是必须顺序调用的流水线。简单任务可由 superagent Worker 直接执行；js-agent-runtime 是库，不是 superagent 的必经执行层。Skill 不另建状态库、常驻循环或结算逻辑。

用户明确要求完整组合时安装四者；其他情况按目标选择。安装、配置和启动是不同结果：仅安装技能或依赖不授权启动模型、开回合、发消息、发布包或创建远端仓库。用户已明确授权的后续操作直接继续，不逐步重复确认；账号验证等必须由本人完成的步骤再交接。

以目标项目为作用域。保留已有状态库、工单、冻结输入、审核决定和会话绑定；不得通过删除/重建状态或手改数据库修复表面错误。业务字段、内容规则、具体候选和运行编号留在宿主项目，不写入技能。

版本与 CLI/SDK 选项以已安装包的帮助、README、类型声明为准。查询 registry 并检查兼容性，不能把本技能记录的版本当作永远最新。使用项目内准确版本，避免 `npx` 无意下载另一个版本。

完成时报告：实际安装/复用的版本、配置与启动状态、验证层级和结果、仍需用户操作的事项。卡片送达、答案保存、Worker 完成和业务结算分别陈述。

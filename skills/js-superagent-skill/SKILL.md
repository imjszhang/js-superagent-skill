# 为项目建立并维护 Project Agent

围绕目标项目的规则、长期任务、历史和成果工作。你是使用本技能的项目操作者；后台协调者与 Worker 执行任务。持续工作由已部署服务承担，本技能不另建状态库或调度循环。

## 先定位项目和已有工作

确认目标项目根目录，读取适用的项目规则与当前任务定义，识别实际 CLI/wrapper、已安装版本和后台归属。已有同目标任务先核对身份与进度，再决定继续、调整或新建；不要把“给项目配 Agent”自动解释成重建环境。项目可包含多项独立任务，执行能力、业务规则和成果路径按项目配置选择。

## 按意图进入流程

- **建立或新增长期任务**：读 [任务设计与交付](references/tasks.md)。把目标落实为可持续维护的任务，明确输入、成果、节奏、人工决定和停止条件；可使用 [任务说明模板](assets/task-brief.md)。检查缺失能力后再接入。
- **安装、接入、升级环境**：读 [安装与配置](references/setup.md)；实际安装需要且兼容的依赖。可先运行 `node <技能目录>/scripts/inspect.mjs --project <项目绝对路径>`，它仅检查安装，不初始化服务或连接账号。升级还读运行维护中的升级段。
- **查看、维护、调整、暂停或恢复任务**：读 [运行维护](references/operations.md)。先区分只读检查、变更后续计划、取消在途执行与恢复失败；不要把用户的状态查询变成一次新执行。
- **飞书接入或审核问题**：按需加读 [飞书接入](references/feishu.md)。优先用 lark-cli 检查配置、授权与消息；生产卡片与答案使用 superagent 已有通道。

## 长期工作必须留下什么

任务要有可追溯的目标、输入与输出边界、执行节奏、限制、审核策略和每轮验收标准；任务历史与记忆留在项目。交付时说明当前处于设计、已创建、已启用、后台已部署还是已验证运行，给出任务入口、当前进度、下一步以及暂停/恢复方法。不要把安装成功、模型完成、业务结果已保存混成一个状态。

长期维护包括沿用历史、检查异常、调整后续定义和安全停止。当前内置长期任务持续到明确停用；不要宣称它能自动判定任意长期目标已达成。需要新业务能力时接入项目适配器，不把联网或制作指令塞进不支持这些能力的内置类型。

## 组件与操作边界

- js-superagent：持久工单、协调执行、会话与人工输入。
- js-longrun：任务定义、回合、额度、审核核验和结果采纳。
- js-agent-runtime：按需使用的具体执行适配，不是所有 Worker 的必经层。
- lark-cli：飞书接入与诊断，不是生产回调处理器。

按目标选用组件；明确要求完整组合时安装四者。安装、创建、启用和真实执行是不同动作：仅安装技能或依赖不授权开回合、发消息、对外发布或创建远端仓库。对用户已授权的工作连续推进，不重复询问；账号验证或不可推断的关键决定才交接。

保留原状态库、工单、冻结输入、决定和会话绑定，不手改运行状态制造成功。业务规则与私人项目名称、目录、候选、消息、账号和验收数据留在目标项目；公开示例使用独立虚构材料，不从真实任务复制再仅替换名称。

命令与字段以所用版本的 help、公开文档和类型为准；升级时核对 registry、engines 与 peer。使用项目准确版本和既有 wrapper，避免临时下载不同版本或遗漏宿主业务路由。

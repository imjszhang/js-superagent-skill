# 协调者的项目知识

部署 Project Agent 时，为协调者准备可维护的项目背景。当前聊天读过的 README、规则和资料不会自动进入后台；工单库也不能代表项目的全部工作。

## 目录与内容

通过目标项目安装的 js-superagent 公共路径接口 `projectStateDirectory(projectRoot)` 确认项目专属运行时目录，在其中使用 `knowledge/`。不要手工拼接项目路径编码，不放进共享用户目录，也不增加 `coordinator/` 层级。

```text
<项目专属运行时目录>/
  knowledge/
    project.md
```

默认只准备 `project.md`，按[项目知识模板](../assets/project-knowledge.md)从真实项目资料提炼；没有足够依据时注明未确认，不填造出的目标、进度或能力。已有文件先读取并保留作者修改，不因重新部署或技能升级而覆盖。

知识目录直接子级的每个 `.md` 普通文件对应一个逻辑知识条目：以文件名作为稳定身份，一级标题作为显示名称，没有一级标题时使用文件名；正文作为内容。无需手工逐项登记，也不要求固定文件名或数量。新增、修改、删除文件应反映为对应条目的新增、更新、移除；子目录与非 Markdown 文件不加载，符号链接不作为知识文件读取。

这些条目仅供协调者使用。Markdown 是唯一维护源，运行时载入或同步所得内容不另行维护。写入文件路径不等于已载入文件正文。

## 写什么、保留什么

- 简述项目定位、目标、主要成果、常用业务术语，以及项目工作与工单系统的关系。
- 为重要事实标明项目内来源；给出资料入口以帮助理解和派工，但不能声称协调者已经读过入口指向的全部文件。
- 项目已有规则继续以原文为准，知识文档只保留理解与路由所需摘要，不复制一套工作流。
- 不默认创建 `workflow.md`、`status.md` 或角色指令文件。需要补充主题时再新增；动态状态必须有来源和核对时间，未核对的实时进度交给执行者调查。
- 不收录密钥、凭据或与本项目无关的个人资料。协调职责、权限和派工规则通过角色配置维护，知识条目不扩大授权。

## 启动时同步（0.14.0-alpha.1 兼容接入）

当前共享 `prompts.knowledge` 同时进入 Worker 与协调者，不能用它做角色隔离。技能脚本把每个 Markdown 编译为独立的逻辑知识条目，合并到 `runtime/coordinator` 提示词的受管区块；保留该角色原有文字、其他提示词及共享知识。Worker 组装结果必须不变。这是技能的兼容接入，不是运行库原生目录加载。

`knowledge.mjs` 通过目标项目已安装的包定位状态目录。只读检查使用该固定版本的 SQLite/PromptRegistry 结构；保存使用公开 `configurePrompts` 修订接口。其他包版本明确拒绝，先适配验证再升级，不猜内部格式。

部署顺序：

1. 确认项目已初始化，读取现有模型、提示词、服务安装参数和运行状态。仅安装技能不初始化项目、不写入知识。
2. 用公开 `projectStateDirectory(projectRoot)` 获取状态目录，创建 `knowledge/`，根据真实项目材料填写 `project.md`。已有文件保留，不直接把模板说明当成项目事实。
3. 用下方 `knowledge check` 检查将加载的文件与配置差异。差异返回非零是尚未同步，不是自动获准覆盖。无效文档、超预算或受管区块被手改时先修复；不静默截断。
4. 将项目自己的启动命令指向安装后稳定位置的 `scripts/project-agent.mjs`。它仍调用目标项目固定的 js-superagent，不下载另一份运行库。已有宿主业务路由不能被绕过：若项目已有自定义启动入口，把同样的 `syncKnowledge(root,{apply:true})` 接入原入口启动前，不用通用入口覆盖业务适配。
5. macOS 使用此包装入口执行 `service install`，它通过公开 `createServiceManager({cliPath})` 把包装入口登记为实际后台子进程入口。原服务先核对空闲并停止，保留 mode、凭据文件、端口、日志和代理设置，再卸载旧服务定义并重新安装；状态库、工单和历史不删除。原来停止的服务保持停止；原来运行且获准部署的服务恢复运行。
6. 启动或重启时先同步知识，再在同一进程载入原 CLI，保留其信号处理、就绪回执和心跳。登录启动与异常重启也经过同一入口。同步失败不启动业务；修复后显式重启。安装清单的 `cliPath` 必须指向包装入口，只改 npm 命令不足以接管登录后台。

```sh
# 以下 <skill> 是安装后技能目录，<root> 是目标项目绝对路径
node <skill>/scripts/project-agent.mjs --project <root> knowledge check
node <skill>/scripts/project-agent.mjs --project <root> service install --mode poll --env-file <private-env-file>
node <skill>/scripts/project-agent.mjs --project <root> service start
# 修改 knowledge/*.md 后：
node <skill>/scripts/project-agent.mjs --project <root> service restart
```

前台 `serve`、`run`、`github listen` 也在启动前同步。`knowledge sync` 是显式保存入口，生产环境优先通过重启让文件生效。文件修改不会在当前消息处理中热加载。无需再维护一份 knowledge 文本配置；受管区块只由脚本更新。同样的文件内容不产生新修订，删除文档会移除对应条目；手工编辑区块会被识别并拒绝覆盖。

## 验收与维护

核对：目录属于正确项目；应加载的每个 Markdown 成为独立条目；协调者实际输入含正文；Worker 没有新增这些专属知识；原模型、权限、共享知识、任务与历史不变。停止/启动状态符合本次授权；后台从包装入口启动并到达 ready/healthy。升级技能时保留知识目录，不替换为模板，不顺带升级依赖。

在用户授权范围内用业务项目问题验证：即使工单为空，也能说明项目做什么，并明确哪些进度未查证。组装检查不能代替真实回答验证；不要为验收擅自发消息或创建任务。公开技能只保存方法、工具和通用模板，真实项目知识留在项目专属运行时目录。

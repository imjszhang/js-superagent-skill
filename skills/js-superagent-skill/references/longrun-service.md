# 长期任务的目录与后台管理

用于部署、检查或升级 js-longrun。先用项目现有入口的 `--help` 核对 `service` 和布局配置能力；旧版本没有这些接口时，继续检查其既有 watcher/定时器，不编造命令、不静默换入口。安装清单只证明文件和版本存在。运行包可在机器全局共享，任务目录和服务归属仍按项目独立；按[共享组件与迁移](setup.md)核对选定包及其实际 superagent peer。

## 三层配置与归属

| 层次 | 负责内容 | 维护位置 |
|---|---|---|
| 项目 | 任务根目录、可信业务适配入口 | 项目配置和代码 |
| 任务 | 目标、输入、节奏、额度、审核、成果和历史 | 任务目录 |
| 本机 | 部署参数、进程归属、心跳、日志、最近检查 | longrun 独立机器运行目录 |

支持布局配置的版本读取项目根 `longrun.config.json`，例如：

```json
{"schemaVersion":1,"tasksDir":"automation/tasks"}
```

`tasksDir` 是项目内相对目录；未配置时保留 `research/longrun`。项目根仍是 superagent 项目身份，不能改成任务目录。路径解析使用包的公开布局接口，不在 skill 中复制验证或拼接目录。`task.json` 不能改变项目根、registry、锁或加载任意代码。

**改配置不等于迁移历史。** 已有 registry、任务或在途回合时，先保留原根；不能把新目录里空列表当成没有任务，也不能创建第二套同名任务/预算。本版不提供活动任务目录迁移。新回合冻结实际输入与输出路径，后续收集仍按冻结记录；旧回合、审核证据和合同摘要不重写。业务适配器可能有自己的固定路径，配置 generic 目录不自动迁移它。

目录配置也不扩大材料授权。输入仍按项目根定位；需要读取新目录时，按[材料配置](materials.md)单独核对来源、读取者、输出目的地和在途绑定。

机器运行目录默认 `~/.js-longrun/projects/<项目身份>/`，与 superagent 的工单状态目录分开。非默认机器位置由正式部署入口保存，后续启停和查询沿用原参数。不要手工编码项目路径、共享 superagent 的执行租约，或通过换目录绕过单实例。

业务 state 中的额度、nextDueAt、活动工单绑定以及任务记忆属于长期资料，不是可清理缓存。旧 `working/longrun/control-lock.sqlite3` 是兼容操作锁；新管理版本仍需与旧调用者共享它，不能为了“清理运行目录”删除或搬走。历史试运行、备份和被成果引用的执行记录先分类保留，不批量移动整个目录。

## 一个项目，一组后台入口

longrun 管理一个常驻 `watch` 和一个兜底 `tick` 定时入口；二者沿用同一个项目业务 wrapper。默认每小时检查，调整检查频率不修改各任务自身的冷却和额度。不要把 longrun 塞进 superagent 的 service manager，也不要另开飞书连接或消息消费者。

任务的分钟字段见[任务设计](tasks.md)。部署短间隔任务时，将检查间隔设为项目内最短任务间隔或更短的受支持值。例如，5 分钟任务使用 `--interval-seconds 300`，30 分钟任务可使用 `1800`。保留默认每小时检查会延迟这些任务。多个任务仍共用同一组后台入口；已有服务调整参数时，按下面的切换流程停止并重新安装原 wrapper，保留原任务和启动意图。

macOS 登录后台服务通过 longrun 的 `service install/start/stop/restart/status/health/logs/uninstall` 管理；其他平台按已安装版本实际能力使用前台或宿主进程管理器，不声称已支持同等系统服务。

操作语义：

- `install` 记录入口与安装文件，不启动任务；`start` 加载后台，也不改变 draft/disabled/paused。
- `watch` 只收集。定时器只有显式允许开轮时才通过原门控开启已启用、到期且额度足够的任务。
- `stop` 阻止新的定时操作并等待本地在途提交/结算退出；不取消已提交 Worker，不停止 superagent。任务暂停和工单取消仍按[运行维护](operations.md)分别处理。
- `uninstall` 移除该部署的服务注册，保留任务与审核历史。不同任务共用后台，不因停用一个任务卸载整组服务。
- `status/health/logs` 读取既有观察，不调用 `.init()`、collect、tick、patrol、自动恢复或消息发送。读不到时报告 unknown/unobserved/unavailable，不初始化来制造正常状态。

安装时核对绑定的绝对 Node、入口、环境与路由；generic 项目可用组件检查确认的绝对 npm 包入口，已有宿主 wrapper 必须保留。不要把 PATH 查找或通用 CLI 替换当作自定义 SDK 业务路由迁移。入口参数是参数数组，不能拼接 shell 字符串。安装/启动的具体参数以该版本 help 为准；升级保持保存的参数，不将普通包 CLI 替换宿主入口。

支持这些选项的版本可按以下形式安装。`<wrapper>` 是目标项目实际入口；示例的 `[]` 适用于入口本身已经确定项目的 wrapper，generic CLI 通常需要 `["--project","<root>"]`。仅已授权持续运行时才设置 `--open-rounds true` 并启动：

```sh
node <wrapper> service install --entrypoint <wrapper> --entry-args '[]' --node <absolute-node> --interval-seconds 3600 --open-rounds true
node <wrapper> service start
node <wrapper> service status
node <wrapper> service health
```

上例按小时检查。部署已授权的 5 分钟任务时，将安装命令中的 `--interval-seconds 3600` 替换为 `--interval-seconds 300`，并验证任务定义、运行额度和后台保存的 `intervalSeconds`。首次验收等待系统定时器实际唤起，检查开轮、结算和下一次到期时间。

`--runtime-home <absolute-directory>` 是 service 命令的本机目录选项；后续操作沿用已保存绑定，不在任务定义中设置它。安装先保存参数；启动失败时检查结构化原因，不重复安装覆盖归属记录。

## 健康检查怎样解释

分别报告后台进程、当前运行心跳、最近成功收集、最近定时检查及观察时间。定时器大部分时间没有进程是正常的；下次检查是预计时间，休眠、关机或退出登录会延后。

服务 ready 不能仅由 PID 或 launchd loaded 推断。等待人工审核、正常冷却、暂停和额度用尽是业务状态，不等于服务故障。Worker 完成、longrun 核验结算和生成视图刷新是不同事实；其中一项失败不能覆盖另外两项事实。

longrun 可通过 superagent 已有公开服务健康和项目身份接口检查依赖，无需为部署长期任务修改或升级 superagent。现有 longrun 业务适配器仍可能调用 `createProjectAgent().init()`，因此不把后台全部查询宣称为纯只读，也不借它实现管理查询。健康观察过期时说明时间，不能声称已经取得最新逐工单事实。

## 旧部署切换与回退

1. 记录准确包版本、项目根、任务目录、原 wrapper/参数、两个旧服务标签和运行意图；核对本地 skill 补丁。保存任务/工单/回合绑定、审核证据、额度与 nextDueAt 的基线。
2. 先停止旧定时入口，再停止 watcher，确认归属和实际退出，等待正在进行的本地提交/结算退出。未知所有者、仍有在途操作或停止失败时保留原记录，不删锁/owner、不强杀裸 PID、不启动第二套服务。
3. 在共享操作锁保护下形成一致业务备份。仅升级 longrun 时不停止 superagent；它仍可能收到答案，恢复后由 watcher 补收。不能直接复制运行中的 superagent SQLite 主文件冒充一致备份。
4. 安装指定包和已核对的 skill 副本，核验组件绑定并配置新管理入口；本地切全局或包路径/版本变化时，通过正式卸载/安装更新服务注册，保留全部业务状态。共享包更新前停止全部使用者，不只处理当前项目；保留原任务目录、审核绑定与所有业务规则。只有用户要求发布才发布 npm/标签；本地打包安装与 registry 发布要分别记录。
5. 只恢复原先 running 的部署，验证旧两个入口没有残留、新部署只有一个 watcher 和一个定时器、启动补收及依赖健康。原 stopped、draft、paused、disabled 都继续保持。
6. 新版尚无业务写入时可恢复旧部署；已有新答案或结算时，保留新事实后按支持的恢复路径处理。不能只降包或覆盖旧备份，也不能仅凭 schema 相同判断可回退。

操作锁只串行一次业务写入，常驻单实例和服务控制另有归属保护；不能长时间占住业务锁来阻止第二个 watcher。新版之间的单实例保护也不代表任意旧版可以混跑。安装窗口停止所有旧入口是迁移要求，不承诺零停机。

## 验收与交接

先在隔离项目验证默认/非默认目录、只读状态、并发与恢复，再用目标部署的独立虚构任务验收。真实卡片由原 superagent 通道发送，真实提交由人或支持的真实 UI 完成；不要操作历史业务卡片或注入答案冒充卡片回调。

即时结算记录真实答案、原 Worker 完成、watcher 结算三个时间，期间不手动 collect/tick。定时开轮与兜底另用隔离任务验证，记录实际触发来源；直接运行一次 tick 不能证明系统定时器工作。恢复正常检查频率、停用测试任务并清理临时服务后，再核对原任务历史与运行状态。正常用户提交引起的业务变化如实保留，不能为达到“哈希不变”覆盖它们。
